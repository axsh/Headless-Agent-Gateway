# 仕様書: Codex 1MB制限対応（ステートレス・プロキシ型）

## 背景 (Background)

- **Codex の制限**: Codex CLI は stdin からの入力を 1MB 以内に制限しており、これを超えるとエラー終了する。
- **設計方針の変更**: サーバー側（`agentservice`）で画像を保持・復元する仕組みは、プロキシとしての責務を超え、複雑さを増大させている。
- **現状の課題**: 
    - サーバーが履歴から画像を自動復元するため、意図せず 1MB 制限に達しやすい。
    - 画像データがサーバーに残ることで、ディスク管理やクリーンアップの課題が生じている。
- **解決策**: サーバーは画像データを保持せず、リクエストごとに Coding Agent へそのまま転送するプロキシに徹する。コンテキスト（過去の画像を含めるか等）の管理はクライアント側の責務とする。

## 要件 (Requirements)

### 1. サーバー側バリデーションの強化
- **事前チェック**: Coding Agent へプロンプトを送信する直前に、構築されたデータ全体のサイズを計算し、制限値を超える場合は実行を中断してエラーを返す。
- **エラー通知**: クライアントに対し、プロンプトサイズ制限によるエラーであることを明確に伝える。

### 2. マルチモーダル永続化機能の削除
- **保存の廃止**: アップロードされた画像データをサーバーのディスク（`sessionDir/multimodal` 等）に保存しない。
- **自動復元の廃止**: 過去のターンの画像を履歴から読み込み、現在のプロンプトに自動挿入する処理を削除する。

### 3. API とアダプターの簡素化
- **ステートレス化**: `SendMessage` リクエストに含まれるコンテンツのみを対象として実行する。
- **コンフィグ管理**: 制限値（`max_prompt_bytes`）は `model_profiles.yaml` で管理可能にする（デフォルト 1MB）。

## 実現方針 (Implementation Approach)

### 1. 既存機能の削除
- `shared/libs/go/agentservice/handler.go` から、`BuildMultimodalContent` および画像永続化に関連するロジックを削除する。
- `multimodal.go` の「保存」に関連する関数を削除し、純粋なデータ変換のみを行うようにする。

### 2. サイズバリデーションの実装
- `agentservice/handler.go` またはアダプターの `Send` メソッド内で、最終的に構築された stdin 用プロンプトの `len(bytes)` をチェックする。
- 制限超過時は、SSE ストリームの最初に `type: "error"` イベントを送信する。

### 3. 設定ファイル (`model_profiles.yaml`)
```yaml
coding_agents:
  codex:
    max_prompt_bytes: 1048576 # 1MB
```

## 検証シナリオ (Verification Scenarios)

1.  **1MB制限の検証**:
    *   1MB を超えるリクエストを送信し、サーバーが即座にエラーを返すことを確認。
    *   Codex CLI が起動されないことを確認。
2.  **ステートレス性の検証**:
    *   ターン1で画像を送る。
    *   ターン2でテキストのみを送る。
    *   サーバーがターン1の画像を再利用 **しない** ことを確認（Codex への入力に含まれない）。
3.  **ディスク汚染の防止**:
    *   リクエスト送信後、サーバー上のセッションディレクトリに画像ファイルが生成されていないことを確認。

## テスト項目 (Testing for the Requirements)

- **自動テスト**:
    - `shared/libs/go/agentservice/handler_v2_test.go` にて、画像が保存されていないこと、およびサイズ制限超過時にエラーが返ることを検証。
    - `integration_test.sh --specify TestCodexE2E_Stateless` を新規作成。
